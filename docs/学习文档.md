## 0. 一句话定位

> **一个拍照就能用的购物参谋：VLM 看图 → Agent 决策 → 工具比价/检索 → 给有据可依的建议。**
> 灵魂只有一句：**回答里每一个价格、每一条引用都必须有证据，宁可少说，绝不编造。**

它的核心不是"能比价"，而是**给模型套了一个"证据契约"**——模型只能引用"画面里看到的"和"工具返回的"，否则就被判违规。

## 1. 项目整体概述与目标

### 1.1 它解决什么问题

用户在超市/便利店拍一张货架照片，问一句"这个值不值？有没有更便宜的？"系统完成：

```
拍照 → VLM 读图（结构化感知） → Agent 决策（要不要查工具）
     → 工具（线上比价 / 记忆检索 / 查画像 / 记偏好）
     → 组织回答（带证据、带链接、带引用编号）
     → 证据校验（价格有没有出处、引用是不是真的）
     → 流式输出（边生成边推送，链接先于正文直出）
```

### 1.2 设计目标（按重要性）

| 目标 | 含义 | 落到代码 |
|---|---|---|
| **诚实/可验证** | 每个价格、每条引用都要有出处 | `evidence.py` 证据契约 |
| **离线可复现** | 零 Key 也能跑完整链路 | LLM/VLM/比价/嵌入四层 mock |
| **防幻觉** | 演示数据必须声明、查不到就直说、不猜价格 | 提示词规则 + 证据校验 |
| **流式体验** | 边生成边推，链接先出 | `streaming.py` + SSE |
| **记忆可召回** | 用久了记忆不塞爆 prompt | `rag/` 检索层 |

### 1.3 一次提问的八步数据流

```
① perceive    VLM 读图 → 结构化 JSON（商品/价签/促销/不确定项）
② agent       模型决定：直接答 / 发起工具调用（function calling）
③ tools       执行工具，结果带 evidence 写回
④ （循环）    agent 拿到工具结果再决定（受 MAX_TOOL_ROUNDS 限制）
⑤ confirm     （可选 HITL）草稿含"买/不买"建议时征询用户
⑥ finalize    取最终回答 + 证据校验 + 确定性补全链接 + 落库
⑦ 流式        SSE 逐块推送（delta / links / violations / done）
⑧ 记忆索引    本轮问答增量写入检索库（失败不影响本次）
```

## 4. 关键代码结构与设计思路解析

### 4.1 状态图（`agent/graph.py`）

```
START → perceive → agent ⇄ tools（工具循环，受 MAX_TOOL_ROUNDS=3 限制）
                      ↓
                   confirm（HITL 门）
                      ↓ regenerate（用户拒绝建议 → 回 agent 仅陈述事实）
                   finalize → END
```

节点都是**纯函数**：输入 state，返回"增量更新字典"，由 LangGraph 合并。

| 节点 | 职责 | 关键点 |
|---|---|---|
| `perceive_node` | VLM 读图 | 失败不炸流程，返回"空观察 + 原因" |
| `agent_node` | 调模型，决定调工具还是直接答 | 达到工具轮数上限后**不再下发工具**（防死循环） |
| `tools_node` | 执行工具，结果写回消息与 `tool_results` | 链接尽早推送（先于正文） |
| `confirm_node` | HITL：草稿含"买/不买"建议且开 `SNAP_CONFIRM` 时征询 | 仅 CLI 交互终端生效，Web 自动放行 |
| `finalize_node` | 取最终答案 + 证据校验 + 确定性补全链接 + 落库 | 链接块由**程序确定性补全**，不是模型写的 |

### 4.2 灵魂模块：`evidence.py`（证据契约）

判定"回答里的价格是否都有依据"，三类违规：

| 违规类型 | 触发条件 | 举例 |
|---|---|---|
| 无证据价格 | 回答出现价格，但不在 `allowed_prices()` 集合里 | 模型说"网上一般 99 元"，但工具没返回 99 |
| 未声明演示数据 | 本轮用了 mock 数据但回答没提"演示" | 默认 `PRICE_MODE=mock` 却没声明 |
| 引用不存在 | 引用了 `【记忆:xxx】` 但编号不在本轮检索结果里 | 编造 chunk_id |

`allowed_prices()` 从**三处**收集合法价格：
1. 画面感知（`perception.items` 的价签、`read_text`）；
2. 工具结果里的 `price` 字段（比价）；
3. 工具结果里的 `title/note/text` 文本（含中文数字"十块/十几元"归一化）——**检索片段里的价格也算有依据**。

> 一个关键修复（面试能讲）：画像 facts（用户自己说过的"预算 200 元"）也纳入合法来源——否则会被误判成"无证据价格"。

### 4.3 检索层：`rag/`（RAG 的完整落地）

**为什么要有它**：原记忆是"画像全量塞进 prompt"，用久了必然塞不下——1000 条约 17,630 token，8k 窗口必然截断；检索注入恒定 88 token。

**管线**：

```
切分(300字/重叠60) → 嵌入(真实语义 / 离线词面哈希) → SQLite 存储(chunk+向量BLOB+FTS5)
→ 混合检索(向量+BM25，RRF融合) → 可选重排(LLM / 词面覆盖率) → 作为工具结果交给模型
→ 回答带【记忆:chunk_id】→ evidence.py 做引用 grounding 校验
```

**四个关键取舍（面试必考）**：

1. **为什么不用向量数据库**：几千条以内 SQLite + 余弦暴力检索是毫秒级，零额外依赖、零额外服务；真到十万条再换 ANN 不迟。
2. **向量运算纯 Python（不引入 numpy）**：1536 维 × 千条也就百毫秒，换来零新增依赖、离线可跑。
3. **中文 BM25 的坑**：SQLite FTS5 的 unicode61 会把连续汉字当一个整词，中文几乎检索不到——这里把中文展开成**单字 + bigram** 再入库（查询同样处理）。
4. **混合检索用 RRF 而不是加权求和**：余弦（0~1）和 BM25（负数）量纲不同，加权要对分布敏感；RRF 只用排名，天然可比。

**重排**：真实模式用 LLM 对 Top-20 打分取 Top-5；离线用词面覆盖率（失败自动降级，不影响主流程）。

**诚实边界（务必主动讲）**：未配 `EMBED_API_KEY` 时用的是**词面哈希伪向量**（汉字单字/bigram 哈希到 256 维），只衡量字面重合——"便宜"和"实惠"不会被判相似，**它不是语义检索**。库里按 `embed_mode + dim` 隔离存储，绝不拿伪向量冒充语义检索。

**引用传染**：历史回答入库前会**先剥掉引用编号**（`strip_citations`），否则旧引用会随文本被反复复制，导致引用指向的不是本轮证据。

### 4.4 流式协议（`streaming.py` + `app/server.py`）

事件类型（SSE 帧 `data:` 里的 JSON）：

```
start / phase / perception / tool / links / delta / rollback / violations / done / error
（另有注释帧 ": ping" 作为心跳）
```

三层可靠性保证（面试能讲）：
- **必发结束标识**：`_close()` 保证无论成功/异常/线程半路退出，流一定以 `done` 或 `error` 收尾；
- **180 秒硬超时**：`watchdog` 主动发 `error`，前端不会无限等；
- **心跳**：10 秒无数据发 `: ping`，穿透反代缓冲（配合 `X-Accel-Buffering: no`）。

**"流式结果 == 一次性结果"**是硬约束：流式只是"边生成边推送"，最终返回的 message 与一次性调用同形；`tests/test_streaming.py` 用 `runner.run_once` 对比两者逐字一致来守住这一点。

### 4.5 更多设计取舍

- **为什么不用 LangChain（项目二）**：需要自己控制流式 chunk 组装和工具调用分片合并，抽象层反而挡路，直接写 OpenAI 兼容 client。（项目一反而用了 LangChain——两个选择都有理由，面试能对比讲。）
- **VLM 替代 CV 流水线**：不搞检测/OCR 全家桶，直接让多模态模型输出 JSON，砍掉 75% 复杂度。
- **链接确定性补全**：候选链接由 `finalize_node` 程序化补到回答末尾，不依赖模型主动写链接——守住"说了更便宜就必须给链接"。
- **离线 mock 大脑是确定性规则**：从消息历史解析意图，保证零 Key 可复现、评测可复现。

## 7. 常见问题与注意事项

| 问题 | 处理 |
|---|---|
| 比价结果全是"演示数据" | 默认 `PRICE_MODE=mock`；要真实报价设 `PRICE_MODE=web`（建议配 `TAVILY_API_KEY`） |
| 回答里没有候选链接 | mock 模式本就没有链接；web 模式失败会如实说"没查到" |
| 状态条"正在组织回答"不消失 | 已修（CSS `[hidden]` 覆盖 + 双超时 + 服务端硬超时）；升级最新代码即可 |
| 检索不到历史偏好 | ① 看 `/api/kb` 的 chunks；② 没建索引跑 `--index` 或提个回忆问题；③ 记忆里本来没内容；④ 未配 `EMBED_API_KEY` 是词面检索，同义词召回不到属预期 |
| 手机打不开网页 | Windows 防火墙放行；确认手机和电脑同 Wi-Fi（README Q14） |
| web 模式检索不到价格 | 反爬/JS 渲染所致；国内网络不稳时返回空并如实说明，不假装查到 |

**注意事项（红线级）**：
- 离线 mock 的嵌入是**词面伪向量，不是语义检索**——对外表述必须如实说；
- 检索层**不引入向量数据库、不引入 numpy**，是刻意的工程取舍（面试讲得清才加分）；
- 演示数据必须声明、查不到必须直说，这是"诚实约束"的一部分，**关掉它（`--loose`）就会看到无证据断言上升**——这正是消融实验要证明的东西。
