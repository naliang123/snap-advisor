# 小拍 · 拍照购物参谋 —— 非技术读者学习路径

> 这份文档**不需要你读任何代码**。它用"部门分工"和"看得见的证据"（页面徽章、
> 日志、报告、配置）帮你理解这个项目做什么、怎么跑、怎么验证它真的在按设计工作。
> 想看技术细节，再去读 `README.md`；想看源码，最后再说。

---

## 0. 先看这 90 秒

**一句话**：拍一张货架/商品的照片，问"值不值得买"，它会先看图 → 再查线上价格 →
然后回答你；并且**它说的每一个价格都必须有出处，没有出处就不许说**。

**和常见 AI 问答最大的区别**：它不是"生成一段听起来像那么回事的话"，而是
**先收集证据、再说话、说完还要自检**。所以它经常会说"这个我没查到 / 拿不准 /
这是演示数据"——这不是能力不足，这正是它的设计目标：**宁可少说，绝不编造**。

**你要记住的三个关键词**：
1. **证据契约**：回答里的每个价格，必须能在"画面价签"或"工具查到的报价"里找到；
2. **演示数据（mock）**：没接真实接口时，它会明确告诉你"这是演示数据"；
3. **轨迹日志**：每一步都记在 `data/trace.jsonl`，任何时候都能复盘它到底干了什么。

## 1. 项目整体目标

| 维度 | 说明 |
|---|---|
| **解决什么** | 在超市/电商场景里，"这个价格值不值"的判断需要同时看画面价签、线上行情和你的偏好，人很难当场查全 |
| **怎么做** | 拍照 → 视觉模型读图 → 需要时调用比价工具 → 结合你的偏好 → 给出**有依据**的建议 |
| **设计底线** | 诚实：查不到就说查不到；拿不准就标"拿不准"；演示数据必须声明；**不确定的价格一律不许出现** |
| **额外目标** | 让"Agent 工程"这件事**可讲清楚**：图结构、工具循环、证据校验、评测、消融、流式输出都是可验证的工程件，不是提示词魔法 |

## 2. 核心功能与模块划分（用"公司部门"理解）

| 部门 | 对应文件（仅用于定位，**不需要读**） | 职责 | 你在哪儿能看到它 |
|---|---|---|---|
| **前台**（电脑/手机页面） | `app/static/index.html`、`app/server.py` | 收照片、收问题、把回答**逐字流式**显示、展示证据面板 | 浏览器页面；手机扫码也能开 |
| **总调度**（流程编排） | `agent/graph.py`、`agent/nodes.py` | 规定"先看图 → 再决策 → 可反复调工具 → 最后收尾"的顺序与出口 | 页面上的阶段提示：正在看图… / 正在比价… / 正在组织回答… |
| **眼睛**（视觉感知） | `llm/vlm.py` | 把照片读成结构化清单：商品名、价签、促销文字、**拿不准的地方** | 页面展开"画面感知 JSON" |
| **大脑**（对话与决策） | `llm/client.py`、`agent/prompts.py` | 决定"直接回答"还是"先查一查"；生成最终回答；人格与规则写在提示词里 | 回答正文；页面的流式文字 |
| **手**（工具） | `tools/registry.py`、`tools/price.py` | 三件事：**比价**（查线上报价与链接）、**记偏好**、**查画像**；每个结果都带来源标签 | 页面展开"工具结果"；回答末尾的候选链接卡片 |
| **记忆库** | `memory/store.py` + SQLite | 长期记住你的偏好（预算、尺码等）和每次对话存档 | 页面"最近对话"；`data/memory.db` |
| **质检部**（证据契约） | `evidence.py` | 逐字检查回答里的每个价格：有没有依据？演示数据有没有声明？ | 页面徽章：**绿色"证据校验通过"** 或 **红色"无证据价格"** |
| **黑匣子**（轨迹日志） | `logging_utils.py` | 每个节点干了什么，一行一条 JSON | `data/trace.jsonl` |
| **考试与对照实验** | `evals/` | 5 个用例跑分；还有"开/关证据约束"的对照实验 | `data/eval_report.json`、`data/ablation_report.json` |

**三种运行模式**（非常重要，决定了你看到的是"演示"还是"真实"）：

| 层 | 没配 Key 时 | 配了 Key 时 | 在哪看 |
|---|---|---|---|
| 大脑（LLM） | 离线规则演示 | 真实模型 | 启动横幅 / 页面角标 |
| 眼睛（VLM） | 用内置示例标注 | 真实视觉模型 | 启动横幅 / 页面角标 |
| 比价 | 演示报价 | 真实网页检索 | 启动横幅 / 工具结果里的 `evidence` |

> **零 Key 也能完整跑通全链路**（含工具调用、证据校验、流式输出），这是刻意的：
> 方便演示、测试和面试讲解。

## 3. 数据流向（一次提问，从拍照到回答）

可以把它想成一条**流水线**，每一步的产物都是下一步的输入：

```
你的照片 + 问题
      │
      ▼
① 前台接收 ──────────► 照片存入 data/uploads/，问题进入对话
      │
      ▼
② 眼睛看图 ──────────► 产出"画面感知"：商品名 / 价签 / 促销 / 拿不准项
      │
      ▼
③ 总调度打包 ───────► 画面感知 + 你的历史偏好 + "不许编造"的规则
      │
      ▼
④ 大脑决策 ──────────► 两种选择：
      │                  A. 信息够了 → 直接回答
      │                  B. 需要查证 → 发出工具调用（比价 / 记偏好 / 查画像）
      ▼
⑤ 工具执行 ──────────► 比价：核心词提纯 → 电商站点定向检索 → 过滤无关结果
      │                  → 有价格的排前面 → **结果全部带来源标签**
      │                  结果回到大脑（可多轮，最多 3 轮）
      ▼
⑥ 大脑作答 ──────────► 逐块流式推到页面上（你能看着它一个字一个字写出来）
      │
      ▼
⑦ 质检部校验 ───────► 逐字比对：每个价格是否都有出处？演示数据是否声明？
      │                  → 页面显示绿色/红色徽章
      ▼
⑧ 落库与留痕 ───────► 对话存档 + 偏好更新（SQLite）；全程写入 data/trace.jsonl
```

**一句话记住**：*感知提供"画面事实"，工具提供"外部事实"，大脑只负责把它们组织成人话，*
*质检部负责不让它多说一个没依据的数字。*

## 4. 典型使用流程与运行方式

下面所有命令都在项目目录 `D:\code\snap-advisor` 下执行（PowerShell）。

### 4.1 最快的一条路：离线演示（零 Key）

```powershell
.venv\Scripts\python.exe main.py --demo
```

你会看到：**模式横幅 → 画面感知 → 工具调用 → 小拍回答 → 证据校验结论**。
这是理解"一次完整流程"最短的路径，建议第一个跑它。

### 4.2 指定自己的照片和问题

```powershell
.venv\Scripts\python.exe main.py --image "D:\照片\货架.jpg" --question "这瓶洗发水值吗？帮我比价"
```

### 4.3 多轮对话（终端里连续追问）

```powershell
.venv\Scripts\python.exe main.py --chat
```

### 4.4 网页版（电脑 + 手机）

```powershell
.venv\Scripts\python.exe main.py --web            # 默认 http://127.0.0.1:8000
.venv\Scripts\python.exe main.py --web --port 8017
.venv\Scripts\python.exe main.py --web --host 127.0.0.1   # 只允许本机访问
```

启动后会打印：**本机地址**、**手机地址**（局域网 IP）、**二维码图片路径**
（`data/web_qr.png`，双击打开用手机扫码）。手机和电脑连同一个 Wi-Fi 即可，
首次启动 Windows 防火墙弹窗请点"允许"。

页面能做的：拖拽图片 / **Ctrl+V 直接粘贴截图** / 点击选择 / 手机"拍照识别"；
回答**逐字流式输出**；候选商品链接以**可点击卡片**给出；可展开查看感知 JSON、
工具结果、证据校验、历史存档。

### 4.5 让它"回忆"你说过的话（检索功能）

```powershell
.venv\Scripts\python.exe main.py --chat          # 进入多轮对话
> 记住：我不买含硅油的洗发水                      # 先记住一条偏好
> 我上次说过买洗发水要注意什么？                   # 再问它回忆
```

它会去**自己的记忆里检索**（而不是把全部记忆一股脑塞给模型——那样用久了会塞不下），
找到相关的旧记录后回答，并附上可溯源的编号 `【记忆:xxx】`。
想看它检索得准不准，跑：

```powershell
.venv\Scripts\python.exe main.py --rag-eval        # 召回率 / 排序质量
.venv\Scripts\python.exe main.py --rag-ablation    # 三种"找法"的对比实验
```

网页版打开 `http://127.0.0.1:8000/api/kb` 能看到：库里有多少条片段、用的是哪种
"找法"（离线模式会显示 `mock`，即按字面重合找，不是语义理解——这是诚实标注）。

### 4.6 考试与对照实验

```powershell
.venv\Scripts\python.exe main.py --eval        # 5 个用例跑分 → data/eval_report.json
.venv\Scripts\python.exe main.py --ablation    # 证据约束开/关对照 → data/ablation_report.json
.venv\Scripts\python.exe main.py --test        # 28 个单元测试
```

### 4.7 两个"演示开关"

```powershell
.venv\Scripts\python.exe main.py --demo --loose     # 关掉证据约束：故意看它胡说
.venv\Scripts\python.exe main.py --demo --confirm   # 给建议前先问你同意吗（人在回路）
```

> `--loose` 是**非常有说服力**的演示：关掉证据约束后，无证据断言会从 0 变成 4，
> 回答里会出现凭空的"网上行情一般 ￥99 起，建议直接买"。这能直观说明质检部在干什么。

## 6. 循序渐进的熟悉顺序（建议 60～90 分钟）

### 第 1 步：跑一次离线演示（10 分钟）
**做**：`main.py --demo`
**看**：模式横幅 → `[画面感知]` → `[工具调用]` → `[小拍回答]` → `[证据校验]`
**应该得到**：校验显示"通过：回答中的价格均有依据"；回答里带"（演示数据）"字样。
**这一关的意义**：建立"完整链路长什么样"的整体印象。

### 第 2 步：弄清"现在到底是演示还是真实"（5 分钟）
**做**：看启动横幅；网页版再看 `/api/modes` 和页面角标。
**看**：`llm_mode` / `vlm_mode` / `price_mode` / `evidence_strict` 四个值。
**应该得到**：没填 Key 时全是 `mock`；填了对应 Key 变 `real`。
**这一关的意义**：以后你看到任何结果，都能先判断它的数据来源。

### 第 3 步：知道有 41 道"守门测试"（5 分钟）
**做**：`main.py --test`
**看**：用例名（工具契约 / 证据检出 / 主图循环 / Web 冒烟 / 流式一致性 / 链接直出 / 检索与引用校验）。
**应该得到**：全部通过。
**这一关的意义**：知道哪些行为是被自动化守住、不会悄悄退化的。

### 第 4 步：用网页版走一遍真实交互（15 分钟）
**做**：`main.py --web` → 拖一张图进去（或 Ctrl+V 粘截图）→ 问"值不值得买？帮我比价"。
**看**：阶段提示（正在看图 → 正在比价 → 正在组织回答）、逐字流出的回答、
**先于正文出现的候选链接卡片**、回答下方的绿色/红色徽章、展开面板里的 JSON。
**应该得到**：回答里的链接**可以点开**；徽章为绿色；面板里的 JSON 与回答对得上。
**手机党**：扫码打开，点"拍照识别"直接拍货架。

### 第 5 步：用黑匣子复盘一次提问（10 分钟）
**做**：`Get-Content data\trace.jsonl -Tail 12`
**看**：把每一行对上第 3 节的 ①～⑧ 步。
**应该得到**：`perceive → agent(tool_calls) → tool → agent → finalize` 顺序清晰；
`tool` 那行能看到 `engine`（用的哪个检索源）、`dropped`（被过滤掉多少条无关结果）、
`priced`（几条拿到了价格）。
**这一关的意义**：**任何"它为什么这么说"的疑问，都能在这里找到答案**。

### 第 6 步：看对照实验，理解"证据约束"的价值（10 分钟）
**做**：`main.py --eval` 和 `main.py --ablation`，再打开两个报告 JSON。
**看**：评测"工具触发 / 价格引用 / 无证据断言"三项；消融的无证据断言数对比。
**应该得到**：严格模式 0 处无证据断言；关掉约束后出现多处（实测 4 处）。
**这一关的意义**：这是整个项目**最值得讲的一张图**——它证明了质检部不是装饰。

### 第 7 步（可选）：接真实 Key，跑一次真实比价（10 分钟）
**做**：在 `.env` 填 `DEEPSEEK_API_KEY` / `VLM_API_KEY` / `TAVILY_API_KEY`，
`PRICE_MODE=web`，重跑 `--image 你的照片 --question "...帮我比价"`。
**看**：工具结果里的 `evidence`（来源、时间、检索源）与真实链接。
**应该得到**：链接指向真实商品页；**注意**：京东/淘宝价格常由脚本渲染且反爬，
"找到同款在售但页面没露价"是正常结果——它会如实说明，不会编价格。

### 第 8 步（可选）：给非技术同事讲 30 秒
用第 0 节的三句话 + 第 6 步那张对照图，就够了。

## 8. 常见"看起来像 bug，其实不是"的现象

| 现象 | 真实原因 | 去哪儿看 |
|---|---|---|
| 回答里写"（演示数据）" | 没接真实接口，用的是演示数据——**必须声明，这是设计** | 启动横幅 `price_mode` |
| 比价说"查不到有效结果" | 电商有反爬、价格由脚本渲染；无关结果（如股票新闻）已被过滤 | `trace.jsonl` 的 `dropped` / `priced`；README Q15 |
| 状态条一直显示"正在组织回答…" | 旧版页面的样式问题（已修复）；**看正文和链接是否已经出现**，出现了就是已完成 | README Q19 |
| 手机上打不开页面 | 同一 Wi-Fi / 防火墙 / 路由器 AP 隔离 | README Q14 |

## 9. 术语表（一句话，非技术版）

| 词 | 一句话解释 |
|---|---|
| **Agent（智能体）** | 不只会聊天，还会**自己决定要不要去查东西**的程序 |
| **LangGraph** | 用来画"流程图"并严格按图执行的框架：每一步是谁、下一步去哪，都是明确定义好的 |
| **Function Calling（工具调用）** | 模型不说"我需要查一下"，而是**发出一条结构化的调用指令**，程序真的去查，再把结果还给它 |
| **VLM（视觉语言模型）** | 会"看图说话"的模型，这里负责把照片读成结构化清单 |
| **证据契约** | 项目自己定的硬规矩：回答里每个价格都必须能在感知或工具结果里找到出处，否则记违规 |
| **消融实验** | 故意关掉某个部件（这里是证据约束），对比前后差异，用来证明这个部件真的有用 |
| **mock / 演示模式** | 不接真实服务时用的本地假数据，**必须明确声明**，绝不冒充真实 |
| **SSE 流式输出** | 服务器边生成边往页面推送，你能看着文字一个字一个字长出来 |
| **SQLite** | 一个单文件的轻量数据库，这里存你的偏好和对话存档（`data/memory.db`） |
| **HITL（人在回路）** | 给"买/不买"建议之前先问你一句同意不同意（`--confirm`） |
